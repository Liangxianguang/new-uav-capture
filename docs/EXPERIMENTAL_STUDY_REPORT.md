# 部分可观测三维障碍环境中的多无人机协同捕获实验总结

> **文档用途**：本文件是当前仓库实验的论文式技术总结和实验章节底稿，不是对外发表的论文。所有数值均来自仓库中保留的可审计证据；对开发验证、正式锁定测试和未验证方向作了明确区分。
>
> **当前代码版本**：`2860b95`（2026-08-26 审核）
>
> **最新可运行模型**：`V5 exact-reactive recurrent behavior cloning + local CBF`
>
> **正式统计结论的证据版本**：V4 retained-BC + CBF 三训练种子 locked test
>
> **研究边界**：运动学仿真中的捕获半径追逃，不等同于物理接触、捕获网、飞控闭环、真实视觉或实飞验证。

---

## 摘要

本研究构建了一个面向非法无人机拦截任务的部分可观测三维多无人机协同捕获基准。四架同质追捕无人机需要在含圆柱体、立方体和墙体障碍物的三维空间中协同追逐一个逃逸目标；系统同时要求完成捕获、避免障碍物和机间碰撞，并保持在世界边界内。为处理局部观测、障碍物异构性和安全约束之间的耦合，本研究采用参数共享的局部观测策略、形状感知障碍物编码、由质量门控规则专家生成示范的循环行为克隆，以及部署时的局部控制屏障函数（CBF）动作投影。最新可运行模型 V5 使用“每控制步重置循环状态”的 exact-reactive 契约，避免训练序列与部署记忆状态不一致。

正式 V4 三种子 locked test 在 30 个评估 artifact、共 3000 个 episode 上表明：在固定障碍物 S1/S2 场景中，`Policy + CBF` 的协同安全捕获率为 98.7%--100.0%；在随机混合障碍 S3 中为 **75.3% +/- 6.5%**。同一策略去掉 CBF 后，S3 协同安全捕获率仅为 **2.3% +/- 1.2%**，碰撞率为 **97.7% +/- 1.2%**；加入 CBF 后碰撞率降为 **4.7% +/- 1.2%**。这说明本阶段的可部署对象是策略与 CBF 的组合，而不是裸神经网络策略。最新发布的 V5 checkpoint 在独立的 60 个开发验证 episode 中取得 **57/60 = 95.0%** 协同安全捕获、0% 碰撞、0% 边界违规和 100% Transit；但该结果仅来自一个训练种子，不能替代 V4 的正式三种子 locked-test 结论，也不能据此宣称统计显著提升。

**关键词**：多无人机协同；追逃；三维障碍物；部分可观测；行为克隆；控制屏障函数；安全捕获

## 1. 研究背景与问题定义

### 1.1 研究动机

面向低空非法无人机的拦截任务，单架追捕机通常同时面对目标规避、障碍遮挡、局部感知误差与自身安全约束。多机协同可从不同方向逼近目标，但也引入新的机间冲突和信息不一致问题。因此，本研究不把“到达目标附近”作为唯一目标，而把问题定义为：**多架追捕无人机在部分可观测、带三维障碍物的环境中，使至少一架追捕机进入目标捕获半径，同时全过程没有碰撞或越界。**

本阶段的重点是获得可审计、可复现的仿真证据，而不是直接宣称现实世界捕获可行。为此，实验把“追捕是否成功”“轨迹是否安全”“障碍环境本身是否可通行”拆开记录，避免用单一成功率掩盖安全问题。

### 1.2 研究问题

给定四架追捕无人机和一架逃逸目标，研究以下问题：

1. 在圆柱、立方体和墙体混合的三维障碍物环境中，追捕机能否在规定时间内接近目标至捕获半径？
2. 在检测丢失、观测噪声、延迟和丢包条件下，局部观测策略能否保持协同追捕能力？
3. 纯学习策略与“学习策略 + 显式安全过滤器”之间的安全性和捕获效率差异有多大？
4. 在固定场景和随机场景中，结果是否能跨独立训练种子复现？

### 1.3 本阶段的可支持结论

本仓库当前证据支持以下结论：

- 对固定中心障碍物场景，所保留的协同追捕栈可以稳定完成安全捕获。
- 对随机中心混合障碍物场景，正式三种子结果表明该栈实现了**部分但非完全鲁棒**的安全捕获，成功率为 75.3% +/- 6.5%。
- CBF 是当前安全性能的必要组成部分；S3 中裸策略不能安全部署。
- 观测延迟和噪声、狭窄通道以及连续逃逸行为仍是主要难点。

本仓库**不**支持“已经完成实体捕获”“能够在真实视觉输入下工作”“已经在真实飞行器或高保真动力学中验证”“V5 已在三种子 locked test 上超过 V4”等结论。

## 2. 任务、场景与成功判据

### 2.1 三维运动学世界

环境实现位于 [`src/encirclement3d/pursuit_env.py`](../src/encirclement3d/pursuit_env.py)，主配置为 [`configs/capture_radius_pursuit_central_v4_flee.yaml`](../configs/capture_radius_pursuit_central_v4_flee.yaml)。世界和主体参数如下。

| 项目 | 设置 |
| --- | --- |
| 世界范围 | `x,y in [-10, 10] m`，高度 `z in [0.5, 10] m` |
| 时间步长与时限 | `dt = 0.1 s`，最多 250 步，即 25 s |
| 追捕无人机 | 4 架同质追捕机，最大速度 `5.0 m/s`，最大加速度 `6.0 m/s^2` |
| 逃逸目标 | 1 架，最大速度 `3.6 m/s`，最大加速度 `4.0 m/s^2` |
| 机体半径 | `0.25 m` |
| 捕获半径 | `0.80 m` |
| 安全裕度 | `0.35 m` |
| 动力学层级 | 速度级运动学；速度会受加速度和边界约束 |

系统中的障碍物为有限高度三维体：圆柱、轴对齐立方体和墙体。随机 S3 场景在中央区域 `x in [-2.5, 3.0] m` 生成 3--5 个障碍物，且每个接受的场景至少含一种圆柱、立方体和墙体。追捕机与目标出生在障碍区两侧，初始侧向距离从 `6.0/6.5/7.0/7.5 m` 中抽样；目标**不要求**进入中央区或穿越障碍区。

### 2.2 部分可观测与通信条件

策略不能读取目标真值。每架追捕机只使用自己的状态、局部目标 belief、队友信息和附近障碍物描述。基础环境包含：

- 目标检测距离 `14 m`；
- 标称条件下 15% 检测丢失、`0.03 m` 观测噪声、2 步消息延迟、5% 消息丢失；
- `delayed_noisy` 条件下 22% 检测丢失、`0.06 m` 噪声、4 步消息延迟、10% 消息丢失；
- belief 采用时间对齐更新，并在陈旧时衰减速度置信度；
- 最多编码 3 个近邻障碍物，形状感知特征补充每个障碍物的水平半尺寸和圆柱/立方体/墙体 one-hot 类型。

这一设计使“部分可观测”不是仅由随机噪声模拟，而同时包含可见性、目标局部 belief 与延迟队友消息三类信息限制。

### 2.3 协同安全捕获定义

单步环境中的 `safe_capture` 同时要求“最近追捕机到目标的距离不大于 `0.80 m`”和“此前没有障碍物碰撞、机间碰撞或边界违规”。实验层再加入中央障碍物任务约束，形成最终指标 **Cooperative Safe Capture**：

1. 至少一架追捕机进入 `0.80 m` 捕获半径；
2. 发生在 250 步时限内；
3. 本 episode 中没有障碍物碰撞、机间碰撞或边界违规；
4. 至少 2/4 架追捕机曾进入中央障碍区；
5. 目标不要求进入中央障碍区。

这里的“捕获”是**捕获半径事件**，不是机体接触、挂网、夹持或非合作目标的物理失能。代码还记录了 `physical_target_contact` 诊断字段，但它不是当前成功标准，不能混同为实体捕获。

### 2.4 辅助指标

除协同安全捕获率外，实验还记录：普通捕获率、碰撞率、边界违规率、平均捕获时间、最小净空、每架追捕机路径长度、CBF 平均修正量、目标/追捕机中央区进入情况和 Transit。

**Transit** 是独立的通行性诊断：它检查由场景几何和执行净空确定的路线可行性与执行情况。Transit 成功不等于捕获，捕获成功也不保证 Transit 成功；报告中始终将两者分开。

## 3. 最新完成方法：V5 Exact-Reactive Recurrent BC + Local CBF

### 3.1 方法概览

当前发布、可直接运行的策略是 `v5_development_exact_reactive_seed661606.pt`。完整执行链为：

```text
局部传感/延迟消息/障碍物几何
              |
              v
  63 维形状感知局部观测（每架追捕机）
              |
              v
参数共享 128 维 GRU actor（V5：每控制步重置隐状态）
              |
              v
候选 3D 速度指令
              |
              v
局部 CBF 投影：障碍物 + 机间距离 + 世界边界
              |
              v
受加速度和速度限制的运动学执行 -> 捕获/安全终止
```

checkpoint 元数据已复核：局部观测维数为 63，训练用集中式状态维数为 46，actor 隐层维数为 128，动作尺度为 `5.0 m/s`，`recurrent_reset_interval_steps = 1`，SHA-256 为 `535098773be05687e147043435649378532362d479bdc0375842970370ba40ba`。

### 3.2 参数共享、局部观测的循环 actor

网络实现于 [`src/encirclement3d/learning.py`](../src/encirclement3d/learning.py)。四架追捕机共享同一套 actor 参数，但每架输入自身局部观测，因此部署时不依赖全局目标真值。网络由两部分动作均值相加构成：

- 一个两层 `Tanh` 前馈基线分支；
- 一个将局部观测编码后输入 `GRUCell` 的残差分支。

此结构保留了局部条件下的非线性动作映射，并允许在需要时使用时间状态。V5 的核心修正并不是“增加记忆长度”，而是让训练和部署具有完全相同的状态契约：训练序列长度设为 1，部署时每个控制步把 GRU 隐状态重置为零。这样避免了较早版本中“训练时按片段处理、部署时连续滚动状态”可能产生的状态分布失配。因而 V5 应准确称为 **exact-reactive recurrent actor**：网络含 GRU 参数，但有效决策是严格的单帧反应式决策。

选择参数共享的原因是四架追捕机同质且任务对编号应尽量不敏感；选择局部输入的原因是与部分可观测设置一致；选择形状感知编码的原因是圆柱、立方体和墙体不能仅由中心点和等效半径可靠区分。上述理由是架构设计动机，真正的性能提升仍需专门消融实验验证。

### 3.3 质量门控规则专家与行为克隆

训练脚本为 [`scripts/train_capture_radius_recurrent_behavior_cloning.py`](../scripts/train_capture_radius_recurrent_behavior_cloning.py)。规则专家使用动态围捕分工：一架机趋向预测的拦截点，其余追捕机趋向目标周围的分配位置；专家本身同样经过局部 CBF 包装。只把满足预设质量条件的专家轨迹放入训练集，核心门控包括：

- 专家 episode 必须达到 `safe_capture`；
- 必须满足 Cooperative Safe Capture；
- 单个任务最多尝试 8 次生成专家轨迹；
- 若专家拒绝率超过 25%，训练在写入 checkpoint 前停止。

actor 使用 Adam 优化动作均方误差，梯度范数裁剪为 0.5，并把训练损失、验证指标和有效配置写入 TensorBoard 及训练 artifact。采用行为克隆而不是在本阶段直接端到端强化学习的工程原因是：高碰撞追逃环境中，安全终止导致稀疏且高方差的有效数据；质量受控专家能先提供可行的安全行为分布。该选择不是对行为克隆优于强化学习的一般性结论。

历史 V5 exact-reactive 训练在两个冻结专家 archive 上保持 `650:650` 的序列平衡、128 维 actor、64 个 epoch、全速度范围动作尺度，并以 V4 warm start 初始化。该历史 archive 和三个 V4 checkpoint 未随精简仓库发布，因此无法从 clean clone 位级复建历史 V5；仓库发布的是**可重新采集质量门控专家数据的独立训练程序**，不是虚假的位级重训练承诺。

### 3.4 Local CBF 安全过滤

CBF 实现在 [`src/encirclement3d/pursuit_controllers.py`](../src/encirclement3d/pursuit_controllers.py)。策略先输出期望速度，再由安全过滤器投影。对障碍物，定义近似 barrier：

\[
h_o(p)=d_o(p)-r_{\mathrm{drone}}-m,
\]

其中 `d_o` 是到障碍物的净空，`r_drone = 0.25 m`，`m = 0.35 m` 为安全裕度。速度沿外法线的分量被投影到满足离散时间下界的可行侧；同样的限制施加于机间距离和三维世界上下界。过滤器执行 4 次局部投影并再次裁剪最大速度。

选择 CBF 的原因是它在不访问目标真值的前提下，能够对障碍、队友和边界施加显式约束，并可量化“策略命令被改动了多少”。S3 对照实验显示这一组件不是可有可无的后处理，而是当前执行栈安全性的关键部分。

### 3.5 可独立复现的训练契约

发布的 clean-clone 训练配置位于 [`configs/capture_radius_recurrent_behavior_cloning_s3_retrain.yaml`](../configs/capture_radius_recurrent_behavior_cloning_s3_retrain.yaml)。其默认设置为：320 个质量门控专家 episode、学习率 `5e-5`、128 维 hidden、64 epoch、单步序列、batch size 由命令行指定（推荐 16）、训练目标速度尺度 `0.45/0.55`、目标模式 `flee_persistence/s_curve`。训练时会保存专家 archive、其 manifest、有效 YAML、源文件哈希、训练 CSV、TensorBoard event 和 checkpoint，从而支持未来对新训练种子的溯源。

> 注：此处明确写为 `5e-5`，而不是使用历史 V5 的任何未发布设置。历史数据与 checkpoint 的可获得性边界见第 7 节。

## 4. 实验设计与证据等级

### 4.1 场景层级

| 层级 | 场景 | 目的 |
| --- | --- | --- |
| S1 | 单一圆柱 / 立方体 / 墙体 | 检查单类障碍物与安全约束 |
| S2 | 固定混合障碍物 | 检查异构障碍物下的重复稳定性 |
| S3 | 随机中心混合障碍物，3--5 个障碍物 | 检查布局、出生侧、目标机动和感知条件变化下的泛化 |

S3 协议固定了随机种子区间、障碍数量、出生侧、初始距离、目标速度尺度、目标运动模式和观测条件。每个 scene 的 episode seed 与 layout seed 都被写入 artifact，因而同一 scene 可重新评估，不依赖重新随机采样。

### 4.2 正式 V4 locked test

正式结论来自 [`docs/evidence/V4_LOCKED_TEST_REPORT.md`](evidence/V4_LOCKED_TEST_REPORT.md) 和机器可读摘要 [`docs/evidence/V4_LOCKED_TEST_SUMMARY.json`](evidence/V4_LOCKED_TEST_SUMMARY.json)：

- 3 个彼此独立训练的 retained-BC checkpoint，训练种子为 `661201`、`661202`、`661203`；
- 每个 checkpoint 在每个执行条件/场景 artifact 上评估 100 episode；
- S1/S2 使用固定 seed `660501`，S3 使用固定 seed block `647001`；
- 总计 30 个 artifact、3000 个 episode（5 个场景 x RAW/CBF 两种执行 x 3 个训练种子 x 100 episode）；
- 指标的统计单位是**独立训练 checkpoint**，表中为三个训练种子的均值 +/- 样本标准差；
- checkpoint、场景、阈值和超参数在 locked block 打开后均未调节；指标补采集与原 locked artifact 逐 episode 一致。

这使 V4 是当前最强的正式统计证据。

### 4.3 最新 V5 开发验证

最新 checkpoint 的开发记录在 [`docs/evidence/V5_EXACT_REACTIVE_DEVELOPMENT_STATUS.md`](evidence/V5_EXACT_REACTIVE_DEVELOPMENT_STATUS.md)。V5 使用冻结的开发 archive、冻结 S3 验证 block 和固定 CBF/环境协议，但其 locked seed block `647201` 未打开。候选模型先经过固定 CBF 场景门控；只有四个固定场景均为 20/20 的模型才允许跑 60 episode S3 开发验证。

因此，V5 的 95.0% 是有价值的**最新可运行开发结果**，但不是正式、跨三种子的泛化结果。报告中将这两种证据并列呈现，是为了同时回答“现在能运行到什么效果”和“论文中能严谨声称什么”。

### 5.1 正式 V4：固定场景 S1/S2（Policy + CBF）

### 5.2 正式 V4：随机混合障碍 S3 的安全过滤对照

下表是同一 300 个 checkpoint-scene S3 评估在不使用 CBF（RAW）和使用 CBF（CBF）时的结果。该对照直接回答了安全过滤器的贡献。

| 执行方式 | 协同安全捕获率 | 碰撞率 | 边界违规率 | Transit | 平均捕获时间 | 平均最小净空 | 每架路径长度 | 平均 CBF 修正 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| RAW 策略 | 2.3% +/- 1.2% | 97.7% +/- 1.2% | 0.0% +/- 0.0% | 99.0% +/- 0.0% | 4.33 +/- 0.28 s | -0.10 +/- 0.01 m | 5.81 +/- 0.08 m | 0.000 |
| Policy + CBF | **75.3% +/- 6.5%** | **4.7% +/- 1.2%** | 4.7% +/- 1.2% | 99.0% +/- 0.0% | 8.08 +/- 0.77 s | 0.35 +/- 0.01 m | 26.12 +/- 1.39 m | 0.175 +/- 0.008 |

与 RAW 相比，CBF 使协同安全捕获率提高 **73.0 个百分点**，并使碰撞率降低 **93.0 个百分点**。其代价同样清晰：平均捕获时间增加 3.75 s，平均每架路径增加 20.31 m，约为 RAW 的 4.5 倍。这是安全--效率权衡，而不是无代价提升。CBF 后仍有 4.7% 碰撞率和 4.7% 边界违规率，故不应称为“绝对安全”。

此外，CBF 条件下目标中央区进入率为 18.7% +/- 8.5%，追捕机平均中央区进入数为 3.93 +/- 0.02；RAW 条件下相应值为 0.0% 和 3.14 +/- 0.03。这与任务定义一致：目标不被要求进入中央区，但多架追捕机需要在障碍区附近协同行动。

### 5.3 S3 失败模式分析（正式 V4，Policy + CBF）

下列分组把 300 个 checkpoint-scenario 评估合并后作描述性统计。它们用于定位难例，**不**是独立训练种子层面的显著性检验；尤其是样本很小的布局不能作强泛化结论。

| 因素 | 分组 | 评估数 | 协同失败 | 碰撞 | 边界 | 超时 | 解读 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| 障碍数量 | 3 | 102 | 24 (23.5%) | 4 | 4 | 20 | 随机基础难度 |
| 障碍数量 | 4 | 96 | 23 (24.0%) | 5 | 5 | 18 | 与 3 障碍接近 |
| 障碍数量 | 5 | 102 | 27 (26.5%) | 5 | 5 | 22 | 增加障碍物后略变难 |
| 观测条件 | nominal | 159 | 30 (18.9%) | 6 | 6 | 24 | 当前主工作条件 |
| 观测条件 | delayed_noisy | 141 | 44 (31.2%) | 8 | 8 | 36 | 感知/通信退化是最明显的失效因素 |
| 通道 proxy | 0.65--0.80 m | 120 | 28 (23.3%) | 2 | 2 | 26 | 中等净空 |
| 通道 proxy | <0.65 m | 177 | 46 (26.0%) | 12 | 12 | 34 | 窄通道更易安全失效和超时 |
| 目标模式 | flee_persistence | 156 | 43 (27.6%) | 10 | 10 | 33 | 持续逃逸更难 |
| 目标模式 | s_curve | 144 | 31 (21.5%) | 4 | 4 | 27 | 相对更易捕获 |

布局维度中，`cylinder1+box1+wall3` 为 15 次评估中 7 次失败（46.7%），是出现次数足够时最差的组合；`cylinder2+box2+wall1` 为 27 次评估中 3 次失败（11.1%），是该样本中的较优组合。由于不同布局样本数不等、布局和通道宽度存在耦合，这些数字只应指导下一轮难例构造，不能解释为单一障碍物类型的因果效应。

错误类型上，CBF 后多数未成功 episode 表现为超时而非立即碰撞。这表明安全过滤成功地抑制了大量危险指令，却可能使某些狭窄或信息退化场景中的接近速度过保守。一个唯一共享的 Transit 异常出现在 locked episode 68（episode seed `647069`，layout seed `1647069`）：该 episode 的捕获、安全和边界均成功，但目标执行净空为 `0.599890 m` 时 Transit 失败。该异常未用于重新调参。

### 5.4 最新 V5 exact-reactive 开发结果

V5 开发阶段测试了三个 exact-reactive 训练种子。所有候选都通过 archive、初始化、损失有限性和源哈希审计，但采用预注册的固定场景安全门控决定是否继续进行 S3。

| 训练种子 | 固定 CBF 门控（每场景 20 episode） | S3 开发验证（60 episode） | 结论 |
| ---: | --- | --- | --- |
| 661602 | 圆柱/立方体/墙体/S2 均 20/20 | 53/60 = 88.3%，碰撞 3.3%，边界 3.3%，Transit 100% | 因 S3 执行安全门控拒绝 |
| 661604 | 圆柱 20/20，立方体 20/20，墙体 19/20，S2 20/20 | 未执行 | 因固定墙体门控拒绝 |
| 661606 | 四个固定场景均 20/20 | **57/60 = 95.0%**，碰撞 0%，边界 0%，Transit 100% | 当前唯一开发通过 checkpoint |

`661606` 的完整开发验证已在本仓库重新验证。代表性 episode 0 的场景含一个圆柱、一个墙体和一个立方体；使用 CBF 时 4.8 s 安全捕获，最终最近距离为 `0.78284 m <= 0.80 m`。其三维图像、GIF 和 H.264 MP4 位于 [`docs/media`](media/README.md)。

![V5 开发验证中的代表性三维安全捕获帧](media/v5_development_s3_episode0_capture_3d.png)

V5 的 95.0% 与 V4 locked-test 的 75.3% +/- 6.5% **不能直接比较为“进步 19.7 个百分点”**：两者使用不同的评估块，V5 只有一个训练种子，且 V5 locked seed block 尚未打开。严谨表述应为：V5 checkpoint 在已冻结的开发验证集上展示出强性能，值得进入三种子开发重复；它尚未构成对 V4 正式结果的替代。

## 6. 结果解释与研究贡献

### 6.1 主要贡献

1. **建立可复现的三维捕获半径任务。** 任务同时包含目标逃逸、异构障碍、局部观测、延迟/丢失消息、机间安全和边界安全，且发布了场景生成、评估、回放和渲染链路。
2. **明确了“策略 + 安全层”的系统级效果。** S3 RAW/CBF 对照直接显示，学习策略的拦截意图不足以保证安全；CBF 是实际部署栈的组成部分。
3. **把随机场景结果从单个漂亮视频提升为锁定测试证据。** 三独立训练种子、固定 scene seed 和逐 episode artifact 使 75.3% +/- 6.5% 具有明确统计单位和重放边界。
4. **提供了最新可运行 V5 实例与可视化资产。** 用户可从 checkpoint 复现开发验证、导出轨迹并生成俯视/透视三维 GIF 和 MP4，而不是只阅读汇总表。

### 6.2 方法为何有效，以及证据强度

| 组件 | 解决的问题 | 直接证据 | 当前能够得出的结论 |
| --- | --- | --- | --- |
| 形状感知局部编码 | 区分圆柱、立方体、墙体 | 已进入 V4/V5 策略契约 | 是当前方法组成；尚无独立消融证明增益 |
| 参数共享局部 actor | 同质多机协同与去中心部署 | 四追捕机共享 checkpoint 接口 | 满足任务实现需求；尚无与非共享 actor 的对照 |
| 质量门控专家 BC | 降低危险探索和低质示范 | 训练器保存 rejection gate 与 archive manifest | 是可复现训练路径；尚无与 PPO/MAPPO 的正式公平比较 |
| 单步重置的 recurrent actor | 消除训练/部署循环状态不一致 | V5 exact-reactive 开发审计与 checkpoint 元数据 | V5 开发可稳定复现；尚未有三种子 locked 结论 |
| Local CBF | 障碍、队友和边界安全 | S3 RAW/CBF 成对对照 | 对当前栈至关重要，且代价是更长路径与更慢捕获 |

这种写法避免把“方法包含某一模块”误写成“已经证明该模块因果增益”。现有最强因果对照是 **CBF 有/无**；其余组件需要正式消融。

### 6.3 目前达到的实验效果

从视觉与行为层面，当前系统已能展示四机从障碍区一侧出发、绕过或越过有限高度障碍物、持续缩小与目标的距离、在捕获半径触发时冻结并标识 Capture 的完整过程。渲染器会输出：

- 俯视 PNG/GIF/H.264 MP4；
- 透视三维 PNG/GIF/H.264 MP4；
- 障碍体积、三维高度线索、轨迹尾迹、动态捕获半径和捕获冻结帧；
- 与媒体一一对应的 `trajectory.npz` 与 episode JSON。

这证明的是仿真中“捕获半径追逃 + 安全约束”的过程可视化和可重放性，不证明物理网捕或接触捕获。

## 8. 局限性与论文投稿前必须补充的实验

### 8.1 当前局限

1. **动力学保真度不足**：当前是速度级运动学仿真，未包含姿态、推力、风扰、控制延迟、执行器饱和或真实飞控。
2. **感知仍为模型化输入**：尽管含丢失、噪声、延迟和遮挡，目标状态不是由真实相机/雷达检测跟踪网络产生。
3. **捕获模型较简化**：`0.80 m` 半径只表示接近事件，不代表接触动力学、网捕、机械抓取或目标失能。
4. **正式随机场景仍有失败**：S3 CBF 的协同安全捕获率为 75.3%，且存在碰撞、边界违规和超时。
5. **V5 的泛化证据不足**：只有一个 V5 候选完整通过开发门控，尚未满足三独立训练种子的预注册条件，因此未打开新的 locked block。
6. **缺少方法消融和外部基线**：除 CBF 有/无对照外，尚未用锁定协议隔离形状编码、exact-reactive 重置、专家质量门控等模块的贡献，也尚未完成与可复现外部方法的同协议比较。

### 8.2 推荐的下一阶段实验优先级

**优先级 A：先形成可发表的严格学习结论。**

1. 为 V5 预注册恢复/改进方案，固定数据、训练、门控和分析规则。
2. 至少完成 3 个独立训练种子在全部固定门控与同一 S3 开发协议上的通过；未满足则不打开 locked block。
3. 成功后一次性运行新的锁定 block，报告均值、样本标准差、每个种子的原始 episode artifact 和失败类型。
4. 做最小但关键的消融：`Policy + CBF`、RAW policy、去形状编码、不同重置间隔、无质量门控专家。所有消融应保持场景与训练预算一致。

**优先级 B：围绕已定位的失败模式增强鲁棒性。**

1. 专门构造 delayed-noisy 与窄通道测试集，但不在 locked block 上调参。
2. 记录 CBF 修正时间序列和超时前距离曲线，区分“安全层过保守”与“策略目标估计错误”。
3. 用独立测试集比较 belief/预测改进方案，重点报告退化感知条件下的成功率、安全率和时间代价。

**优先级 C：提高到接近真实部署的可信度。**

1. 将速度命令接入经过明确参数标定的六自由度动力学或 SITL，并重新验证 CBF 与实际执行之间的一致性。
2. 用检测/跟踪模块输出替代真值派生 belief，量化误检、漏检、身份切换与定位偏差。
3. 将捕获半径模型升级为经验证的接触、网捕或安全伴飞/引导约束，并重新定义终止条件。
4. 最后再开展硬件在环或实飞测试；这些实验必须有独立安全预案，不能由当前仿真成功率直接外推。

## 9. 结论

本研究已经形成了一个完整、可运行、可重放的三维多无人机协同捕获仿真基准，并给出了从固定障碍物到随机混合障碍物的分层证据。当前最可靠的论文结论是：在部分可观测的随机三维混合障碍环境中，**行为克隆的局部追捕策略与局部 CBF 组成的执行栈**在三个独立训练种子的锁定测试上实现了 **75.3% +/- 6.5%** 协同安全捕获；去除 CBF 后安全性显著崩溃。最新 V5 checkpoint 在开发验证中达到 95.0%，并已提供视频与脚本用于复现，但尚不能替代正式三种子结论。
    
因此，实验状态应被表述为：**已证明在受控运动学仿真中存在可复现的多机协同安全捕获能力，尚未证明在复杂真实动力学和真实感知条件下的稳定实体捕获能力。** 接下来的科学重点不是继续增加展示性场景，而是在不泄漏锁定测试的前提下完成 V5 多种子验证、关键消融和动力学/感知转移验证。
