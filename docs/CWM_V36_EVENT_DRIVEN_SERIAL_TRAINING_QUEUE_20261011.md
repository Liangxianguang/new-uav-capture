# V36事件等待串行队列：不轮询、不提前训练

`scripts/run_cwm36_after_audit.ps1`是操作衔接入口，不是新的科学模型，
不修改正在运行的采集/审计或原GRU/DN-MPC/CBF源码。固定科学参数和
完整证据资格仍由已发布V35/V36原生Python入口决定。

入口仅附着在已存活、命令包含本次完整采集和审计路径的原PowerShell
驱动，核对创建时间并持有实际进程句柄；随后等待OS进程退出事件。
没有周期查询或sleep循环，不重启采集/审计，不暂停其他训练。
该等待队列不是模型训练，不应记为优化进展。

原驱动实际退出0后，必须取得512场景完整采集报告及绑定其精确SHA的
全量独立审计通过报告，核对明确的布尔资格、正整数调用总体及审计
证据清单散列；这些只是轻量启动条件，不能代替V35/V36全部原生调用、
成本/导数、输入精度、TRAIN-only归一化和源码验证。

先核对原数据未变、远端HEAD与本地精确相同、至少1GiB可用物理内存
和25GiB可用D盘空间，再执行固定第一批九模型训练。原生exit0且完整
固定三个模型×三个种子报告通过后，串行执行第二批九模型；第一批
收益门失败也保留失败并完成预注册重复，不换模型/预算或启用增强。
资源最低条件是操作性护栏，不保证整个实验或后续归档资源足够。
资源不足或原生失败时保留状态和输出，不自动重启或恢复。

固定输出为`D:\uav-capture\cwm36-p-20261011`、
`D:\uav-capture\cwm36-r-20261011`，均必须全新。
独占队列目录`D:\uav-capture\cwm36-queue-20261011`保存生成的运行
状态与日志；相同入口的第二个队列因目录存在而拒绝，不能绕过它
另外启动竞争相同输出的训练。定时检查应先核对队列进程/状态，再
决定下一步；PID仅作定位，必须核对实际命令与存活身份。

精确发布此入口后、原审计驱动仍存活时启动：

```powershell

```


宣称重复模型逐位一致、响应有益、holdout授权或部署通过。
