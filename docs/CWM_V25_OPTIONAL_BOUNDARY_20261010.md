# V25：因果响应模型的可关闭接入边界

V23已经完成完整独立审计，但`gru_l2`、`gru_cost_l2`、`cv_l2`、`cv_cost_l2`
全部未通过资格门。因此现在不能把任何V23 checkpoint接入原围捕控制。

V25先实现严格的边界合同：

- `off`不加载模型、不读取输入、不调用预测，返回空预测，保留调用方原动作路径。
- `shadow`只允许离线观察，永远没有控制资格。
- `guarded`同时要求离线资格和全部在线合同。
- 模型加载失败、输入/输出非法或预测异常，返回空预测，不能把目标预测当成无人机动作。
- 适配器不生成候选、不修改DN-MPC迭代、不触碰local CBF和安全参数。

已增加`experiments/cwm_v25/original_entry_boundary.py`，在真实历史
`run_episode`入口中于未改变的DN-MPC计划完成后调用边界，并对`off`、
资格拒绝、受控加载/推理失败和合成shadow进行代表性回放。物理结果不仅
逐字段比较，还与未包裹入口以及胶囊历史记录比较；defender/target轨迹、
DN-MPC计划和CBF后命令必须精确一致。资格拒绝使用V23真实失败状态，
故障注入只在不具备控制资格的shadow模式进行。

重要局限：加载/推理故障输入中的history/relative/CV为形状合法的零值
测试夹具，不是真实学习模型的公开输入。它只验证计划完成后的故障注入
边界，尚未完成局部顺序求解器中的实际学习模型集成，不能宣称整个增强
模块原入口回退已充分验证，也不能覆盖V23失败结论。
完整原8Level/新场景闭环、顺序/自生成候选、延迟和资格证据绑定仍需验证。
胶囊配置实际列出level0–8（含初始level0）；报告保留原编号，不将本次
level5/6的两个回放冒称为全Level覆盖。

预测目标形状为[N,8,3]，联合动作形状为[N,8,4,3]，两者严格分开。公开
输入复制后才给模型，加载/预测消耗的CPU Torch/Python/NumPy RNG会恢复，
不初始化CUDA。资格标志只接受布尔True，不接受字符串/数字truthy值。
原GRU特征保持，公共CV/运动校准参考显式返回；锚响应严格零，参考在
候选间严格一致。未来资格记录与完整独立验收证据的绑定仍需入口集成
验证，不能把合成全True测试当成真实模型合格或自动部署许可。
