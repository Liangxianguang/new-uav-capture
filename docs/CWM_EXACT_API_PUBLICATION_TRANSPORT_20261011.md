# Git HTTPS故障时的同对象发布通道

2026-10-11多次Git HTTPS连接到github.com失败，但官方api.github.com
可读。只读核对研究分支仍为
`8a28b342b18da2664a1e64ebf8ef0f2df5f7da94`，不是已经发布本地新报告。
既有SSH严格主机身份检查未通过；没有添加主机密钥、改变网络/
Git配置或创建新凭据。

`scripts/publish_exact_github_api.py`提供限定仓库/研究分支的备用
传输，默认只读。显式`--publish`才允许使用既有非交互Git凭据，
依次上传本地Git对象。每个blob、tree、commit的API返回SHA必须
精确等于本地对象；不重新生成作者、时间或提交消息，不把近似内容
当相同提交。单父无签名常规文件之外的对象拒绝，不涉及原模型目录
和用户未跟踪文件。前后核对远程HEAD，PATCH固定`force=false`。
任一SHA/并发状态不符就不更新分支；对象写入不冒充分支发布成功。
拒绝API重定向，不输出或保存凭据/请求头/凭据管理器诊断内容。

V32仅增加只读发布身份核验的API备用通道，仍要求远程HEAD精确等于
本地HEAD、源码/协议/传输工具与该提交字节相符；全部运行源码快照
包含此工具。没有改变科学输入、模型选择、诊断统计或原失败门。
此前冻结V28/V30发布工具和正在进行的归档源码均未修改。

传输工具的17项模拟测试包括SHA漂移拒绝、并发远端拒绝、路径/模式
限制、非force更新、保留时区/消息、凭据不日志及重定向拒绝；测试
不是实际发布成功证据。实际发布必须另看命令exit0和最终远端SHA。
V32追加3项模拟测试确认备用通道不能豁免精确HEAD验收。
